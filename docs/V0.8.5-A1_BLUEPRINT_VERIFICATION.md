## 1. Executive Verdict

A comprehensive technical audit of the initial V0.8.5 Global Source Blueprint was performed against the live system implementation, PostgreSQL production database, and external web endpoints.

### Key Audit Findings:
1. **Market Universe Restored:** The initial draft accidentally substituted three assets (`USD/CNY`, `Copper`, `VIX`) in narrative text. The canonical universe has been audited against the existing PostgreSQL database seeds and strictly **restored and locked to the original 16 assets** defined in V0.6.
2. **Endpoint Reality Verified:** Empirical HTTP requests to candidate endpoints revealed that several commonly assumed feeds (Stooq CSV, UN News legacy RSS, ReliefWeb v1) are **dead or deprecated (HTTP 404 / 410)**. They have been officially **REJECTED** and replaced with verified live alternatives (Finnhub/Yahoo Finance, ECB reference rates XML, US Treasury daily yields XML, and RBI official RSS).
3. **Quality Framework Hardened:** Naive metrics like "raw event yield $\ge 25\%$" and "aggregate primary ratio $\ge 35\%$" have been replaced with a rigorous, disaggregated multi-dimensional framework measuring event precision ($\ge 85\%$), false-positive rate ($< 10\%$), text span grounding, and domain-specific primary ratios.
4. **Architecture Scalability Mandate:** The audit confirmed that the current inline synchronous extraction loop in `scheduler_service.py` cannot scale past 5–10 sources. Decoupling network fetching from document processing via an asynchronous queue is confirmed as **Step 1 prerequisite**.

**Verdict:** The corrected blueprint provides a realistic, verified, and technically sound architectural foundation. **Implementation must not begin until formal user approval is granted.**

## 6. Event Quality Metrics Framework

The naive single metric of "event yield $\ge 25\%$" is rejected. The platform must satisfy a **6-dimensional quality evaluation**:

```
Quality Index = (Precision × 0.30) + (Recall × 0.25) + (1 - FalsePositiveRate × 0.20) + (1 - DuplicateRate × 0.15) + (ProvenanceScore × 0.10)
```

1. **Event Precision ($\ge 85\%$):** Evaluated against a gold-standard validation set of 100 verified news items. At least 85 of every 100 extracted events must represent genuine real-world intelligence incidents.
2. **Domain-Specific Recall ($\ge 75\%$ for Conflict & Central Banking; $\ge 60\%$ General):** Evaluated by injecting benchmark documents with known incidents; the extractor must successfully capture at least 75% of them.
3. **False-Positive Rate ($< 10\%$):** Fewer than 10% of generated events may originate from non-intelligence text (sports match previews, entertainment commentary, lifestyle features).
4. **Duplicate Event Rate ($< 5\%$):** Fewer than 5% of extracted events may represent duplicate records that failed to cluster into an existing `EventCluster`.
5. **Unsupported-Event Rate ($< 2\%$):** Every extracted attribute (actors, casualty numbers, rate deltas) must be directly traceable to an exact text span in the parent document.
6. **Calibrated Event Yield ($20\%\text{--}35\%$):** Steady-state ratio across a balanced multi-tier fleet.

## 7. Geographic Coverage & Regional Health Metrics

To ensure genuine global coverage, the platform replaces the simple "source count" metric with **regional operational criteria**:

### 4 Mandatory Criteria per Region:
1. **Source Independence:** At least **2 independent operational publishers** originating within the regional theatre.
2. **Domain Breadth:** Coverage must include both geopolitical/security developments AND economic/trade dynamics.
3. **Uptime Continuity:** Verified sources must maintain $\ge 95\%$ polling success over 7 consecutive days.
4. **Event Production:** The region must produce $\ge 2$ structured events per week.

### Regional Acceptance Gate for V0.9:
- **Zero regions with `NONE` rating.**
- **At least 9 of the 11 regions rated `GOOD` or `PARTIAL`.**

## 8. Knowledge Graph Relationship Quality Metrics

The raw count target of "$\ge 100$ relationships" is refined to prevent uncalibrated graph clutter. Every edge in `entity_relationships` must satisfy:

1. **Typology Adherence:** Must match one of the 21 formal relationship types (`allied_with`, `sanctioned_by`, `member_of`, `attacks`, `operates`, etc.).
2. **Confidence Calibration ($\ge 0.80$):** Extraction confidence must equal or exceed 0.80.
3. **Text Span Provenance:** The edge record must store the exact sentence and character offset where the relationship was stated in the parent document.
4. **Temporal Validity Bounds:** Edges must specify `valid_from` and `valid_to` timestamps where applicable.
5. **Duplicate Edge Prevention:** Database uniqueness constraint on `(source_entity_id, target_entity_id, relationship_type)`.
6. **Unsupported Edge Rate ($< 2\%$):** Zero fabricated or inferred relationships without explicit text evidence.

## 9. Macroeconomic Ingestion Schedule & Release Requirements

Economic indicators do not adhere to generic 5-minute polling. They follow strict institutional release calendars:

1. **CPI / Inflation:** Monthly (Second week of month, 08:30 EST / 10:00 CET via FRED/Eurostat). Ingests Previous, Consensus, Actual.
2. **Employment / Payrolls:** Monthly (First Friday of month, 08:30 EST via FRED `PAYEMS` / `UNRATE`). Captures prior-month revisions.
3. **Central Bank Policy Rates:** Scheduled meeting dates (FOMC, ECB Governing Council). Event-driven polling to extract rate delta in basis points.
4. **GDP / Growth:** Quarterly (Advance, Preliminary, and Final estimates via OECD / World Bank). Tracks estimate revisions explicitly.
5. **Trade Balances:** Monthly via national customs bureaus.

## 10. Architecture Scalability & Decoupling Mandate

### The Architectural Flaw in Current Code
In `backend/app/services/scheduler_service.py`:
- Sequential loop over due sources blocks on each HTTP request.
- Inline pipeline execution (`ingest_from_source(trigger_pipeline=True)`) runs entity extraction, event parsing, clustering, and market correlation *synchronously inside the network fetcher*.
- At 15+ sources, a single burst of 25 new articles takes $>30\text{s}$, triggering the 20-second timeout and falsely flagging healthy sources as failed.

### Decoupled Worker Queue Architecture (Mandatory for V0.8.5):
```
Scheduler Loop
   └── Concurrent Fetcher (asyncio.gather / Semaphore=10)
         └── HTTP Fetch & SHA-256 Deduplication
         └── Insert RAW Documents to DB
         └── Enqueue doc_id to asyncio.Queue
                     │
                     ▼
Async Worker Pool (2–4 Persistent Background Tasks)
   ├── Worker 1: Entity Normalization & NER
   ├── Worker 2: Event Taxonomy Parsing
   ├── Worker 3: Clustering & Knowledge Graph Edges
   └── Worker 4: Market Correlation & Alerts
```
