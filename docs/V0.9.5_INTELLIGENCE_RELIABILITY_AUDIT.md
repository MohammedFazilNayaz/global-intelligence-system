## Phase A & C — Forensic Source-by-Source Audit Matrix

Each of the 28 registered sources in the production registry was forensically audited across 18 operational dimensions.

### Operational State Taxonomy (7 States)
- **`HEALTHY`**: Active, zero consecutive failures, upstream reachable, producing fresh content within expected cadence multiplier (<48h).
- **`DEGRADED`**: Intermittent failures ($1 \le \text{consecutive} < 3$) or partial parses.
- **`STALE`**: Upstream returns HTTP 200, but no new content published within cadence threshold.
- **`FAILED`**: $\ge 3$ consecutive failures, permanent upstream DNS/HTTP errors, or Cloudflare/WAF denial.
- **`DISABLED`**: Explicitly deactivated (`active = False`) due to upstream obsolescence.
- **`AUTH_REQUIRED`**: Upstream requires commercial/institutional API key/token.
- **`RATE_LIMITED`**: Upstream returned HTTP 429 rate limit.

## Phase B — Continuous Monitoring & Decoupling Telemetry

### The Freshness vs Check Cadence Fallacy
Prior to V0.9.5, `compute_source_freshness_status` checked only `last_successful_fetch_at`. Because the autonomous scheduler polled every 300 seconds, stale feeds that had not published in weeks were marked `CURRENT`.
**V0.9.5 Fix**:
1. **Explicit Decoupling**:
   - `LAST_CHECKED` (`last_successful_fetch_at`): Time when backend network request completed.
   - `LAST_NEW_CONTENT` (`last_successful_ingestion_at`): Time when new, non-duplicate documents were actually discovered and parsed.
2. **Freshness Invariant**: A source is `CURRENT` if and only if:
   $$\text{now} - \text{latest\_published\_at} \le 48\text{ hours} \quad \text{AND} \quad \text{consecutive\_failures} == 0$$
3. **Run Telemetry**: Every execution now persists 14 fields in `IngestionRun.processing_stats`:
   `scheduled_at`, `started_at`, `completed_at`, `request_duration_ms`, `http_status`, `items_received`, `new_items`, `duplicate_items`, `parse_failures`, `processing_failures`, `last_published_at`, `last_new_document_at`, `consecutive_failures`, `next_scheduled_at`.

## Phase E, F & G — Structured News Intelligence Model

### 21-Field Event Intelligence Dossier Architecture
Implemented in `backend/app/schemas/dossier.py`, `backend/app/services/dossier_service.py`, and endpoint `GET /api/v1/intelligence/events/{event_id}/dossier`:

1. `what_happened`: Title, summary, domain, timestamp, canonical location.
2. `why_it_matters`: Calibrated importance score, importance grade (`CRITICAL`, `HIGH`, `MODERATE`), narrative cluster context.
3. `directly_involved`: Primary actors exercising agency (`EvidenceClass.DIRECT`).
4. `directly_affected`: Entities targeted, impacted, or sanctioned (`EvidenceClass.DIRECT`).
5. `potential_beneficiaries`: Structural or commercial upside, phrased neutrally (`EvidenceClass.ANALYTICAL_IMPLICATION`).
6. `potential_exposures`: Vulnerabilities and secondary supply risks (`EvidenceClass.ANALYTICAL_IMPLICATION`).
7. `affected_countries`: Verified state jurisdiction connections (`EvidenceClass.DIRECT`).
8. `affected_companies`: Named corporate or financial institutions (`EvidenceClass.DIRECT`).
9. `affected_sectors`: Macro sectors mapped to supply disruptions (`EvidenceClass.ANALYTICAL_IMPLICATION`).
10. `commodity_connections`: Linked energy, metals, or agriculture assets (`EvidenceClass.OBSERVED`).
11. `currency_connections`: Sovereign FX pairs exhibiting co-movement (`EvidenceClass.OBSERVED`).
12. `equity_connections`: Regional benchmark indices (`EvidenceClass.OBSERVED`).
13. `rate_connections`: Sovereign bond yields and policy rates (`EvidenceClass.OBSERVED`).
14. `economic_indicators`: CPI, GDP, and central bank statistics (`EvidenceClass.OBSERVED`).
15. `geopolitical_connections`: Bilateral treaties, sanctions, alliances (`EvidenceClass.DIRECT` or `HISTORICAL_ASSOCIATION`).
16. `related_events`: Sibling events in the same narrative cluster (`EvidenceClass.DIRECT`).
17. `related_entities`: Contextually mentioned entities (`EvidenceClass.DIRECT`).
18. `market_observations`: Empirical prices and returns during event window (`EvidenceClass.OBSERVED`).
19. `source_evidence`: Original URLs, publication times, and SHA-256 hashes (`EvidenceClass.OBSERVED`).
20. `confidence`: Calibrated extraction confidence score $\in [0, 1]$.
21. `last_updated`: Pipeline synthesis timestamp.

### Strict Non-Hallucination & Neutral Phrasing Rule
- All fields default to `[]` or `None` if evidence is absent.
- Predictive statements, automated trades, and forward-looking price targets are strictly forbidden.
- Impact fields mandate neutral prefixes:
  - `"Potential beneficiary: Alternative supplier or commercial partner..."`
  - `"Potential exposure: Downside vulnerability to secondary sanctions..."`
  - `"Potential downstream effect: Maritime transit friction..."`
