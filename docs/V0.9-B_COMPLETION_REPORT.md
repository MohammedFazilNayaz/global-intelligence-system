## 2. ARCHITECTURE CHANGES

### 2.1 Reusing Existing Intelligence Models Without Schema Duplication
Per the V0.9 Blueprint, **no duplicate geographic database was created**. The engine consumes the existing database schema:
- `ExtractedEvent` (`metadata_`, `event_type`, `description`, `importance_score`, `created_at`)
- `Entity` (`name`, `entity_type`)
- `DocumentEntity` (`document_id`, `entity_id`)
- `Document` (`source_id`, `published_at`)
- `Source` (`name`, `region`, `domain`, `country`, `is_primary`)

Geographic context is dynamically derived at read time using deterministic normalization rules and cached provenance models.

### 2.2 Strict Read-Only Consumer Architecture
All geo endpoints execute purely as read-only HTTP GET requests with SQLAlchemy `db.query()`. The Globe layer does **not**:
- Trigger collectors, ingestion runs, or scheduler pipelines.
- Mutate events, entities, or relationships.
- Record synthetic market observations.
- Modify database state in any way.

## 3. GEOGRAPHIC DATA CONTRACT

### 3.1 Four-State Location Model
| Location State | Semantic Definition | Point Coordinates (`coordinates: [lon, lat]`) | Example Source |
| :--- | :--- | :--- | :--- |
| **`RESOLVED`** | Authentic coordinates from sensor telemetry or authoritative scientific sources. | Present (e.g. `[142.37, 38.30]`) | USGS Earthquake Feed, verified GPS sensors |
| **`APPROXIMATE`** | Known municipality, district, or verified municipal centroid. | Present (Centroid point) | Tokyo, Kyiv, Washington DC municipal centroid |
| **`REGIONAL`** | Large country, maritime corridor, or sub-continental region without authentic point. | `null` (Geometry is null) | Ukraine, Red Sea, Persian Gulf, East Asia |
| **`UNRESOLVED`** | No sufficiently reliable geographic anchor identified. | `null` (Geometry is null) | Macro-economic papers, global statements, corrupt coords |

### 3.2 Strict Anti-Fabrication Principles
1. **Never fabricate point coordinates**: Country-level events never receive artificial point pins.
2. **Never randomly jitter coordinates**: No synthetic dispersion or decorative offset algorithms.
3. **Never represent inferred centroids as sensor data**: Provenance explicitly distinguishes `SENSOR` from `MUNICIPAL` and `COUNTRY`.
4. **Strict Coordinate Range Bounds**: Latitudes outside $[-90.0, 90.0]$ and longitudes outside $[-180.0, 180.0]$ are strictly rejected and quarantined as `UNRESOLVED`.

## 4. COORDINATE PROVENANCE

Every spatial point or regional designation is packaged with a complete `CoordinateProvenance` schema:
```json
{
  "source": "USGS Earthquake Hazards Program",
  "source_type": "SENSOR",
  "precision": "EXACT_SENSOR_POINT",
  "location_state": "RESOLVED",
  "resolved_at": "2026-09-12T16:00:00Z",
  "confidence": 0.99,
  "verification_notes": "Authentic sensor coordinates provided by USGS telemetry"
}
```

### Supported Types & Precision
- **Source Types:** `SENSOR`, `OFFICIAL_SOURCE`, `GEOCODED`, `MUNICIPAL`, `COUNTRY`, `REGIONAL`, `UNKNOWN`.
- **Precision Levels:** `EXACT_SENSOR_POINT`, `BUILDING_OR_FACILITY`, `MUNICIPAL_CENTROID`, `DISTRICT_OR_PROVINCE`, `COUNTRY_LEVEL`, `MARITIME_ZONE`, `REGIONAL_POLYGON`, `UNKNOWN`.

## 5. MARITIME AND MULTI-LOCATION HANDLING

### 5.1 Maritime Events
- Monitored maritime zones: Red Sea, Persian Gulf, Gulf of Oman, Strait of Malacca, Bab el-Mandeb, Taiwan Strait, Mediterranean Sea, Baltic Sea, Black Sea, South China Sea, Arctic Ocean, Gulf of Aden.
- Maritime regions are classified as **`REGIONAL`** with `is_maritime: true` and `point: null`.
- They are never forced into an arbitrary point pin in the middle of the ocean unless authentic marine sensor or AIS coordinate data is attached.

### 5.2 Multi-Location & Bilateral Events
- Events involving bilateral conflicts, international summits, or cross-border treaties specify:
  - `primary_location`: The primary site or first grounded participant.
  - `locations`: An ordered list of all involved geographic locations (`GeographicLocationItem`), each retaining independent `location_state`, `country`, and provenance.
  - `is_multi_location`: Boolean flag (`true` when $\ge 2$ locations are attached).

## 6. API SPECIFICATION

### 6.1 Endpoints Implemented
| Method | Path | Description | Query Parameters |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/geo/features` | RFC 7946 GeoJSON FeatureCollection | `min_lon`, `min_lat`, `max_lon`, `max_lat`, `location_state`, `event_type`, `region`, `country`, `min_importance`, `max_age_hours`, `include_unresolved`, `limit`, `offset` |
| `GET` | `/api/v1/geo/events/{event_id}` | Full geographic context for a single event | `event_id` (path) |
| `GET` | `/api/v1/geo/unresolved` | Paginated queue of spatially unresolved events | `limit`, `offset`, `event_type`, `min_importance` |

### 6.2 Error & Boundary Behavior
- Invalid bounding boxes (`min_lat > max_lat`, `min_lon > max_lon`): Returns `400 Bad Request`.
- Non-existent event ID: Returns `404 Not Found`.
- Read-only protection: Endpoints reject non-GET verbs (`POST`, `PUT`, `DELETE` return `405 Method Not Allowed`).
