## Phase 1 — Ingestion Architecture: Decoupled Fetch & Process Workers

### 1.1 Architectural Audit of Current Bottleneck
In `backend/app/services/scheduler_service.py` and `backend/app/services/ingestion.py`:
- `IngestionScheduler._tick()` iterates sequentially over due sources.
- For each source, `_sync_ingest_source()` calls `ingest_from_source(db, source, trigger_pipeline=True)`.
- Inside `ingest_from_source()`, newly inserted documents synchronously trigger `pipeline_service.process_document_end_to_end(db, doc_id)`.
- This runs Entity Normalization, Event Extraction, Clustering, Relationship Extraction, and Market Correlation *synchronously inside the network fetcher thread*.
- **Consequence:** A batch of 20 articles taking 500ms each = 10s processing + 3s fetch = 13s. With 15 sources, sequential execution takes $>60\text{s}$, causing `asyncio.TimeoutError` (per-source timeout is 20s), false failure reports, and pipeline stalls.

### 1.2 Target Architecture: Decoupled Worker Queue (Modular Monolith)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       ASYNC SCHEDULER & PIPELINE                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  Scheduler Loop (Every 5s)                                                  │
│    │                                                                        │
│    ├── Market Telemetry Poller (Every 60s) ──> Fetch 16 Assets ──> DB       │
│    │                                                                        │
│    └── Source Poller (Concurrent Fetchers, Semaphore=10)                    │
│          ├── BBC Fetcher ────────┐                                          │
│          ├── Fed Press Fetcher ──┼──> Fast HTTP/XML Fetch                   │
│          ├── USGS GeoJSON Fetch ─┼──> SHA-256 Deduplication                 │
│          └── MercoPress Fetch ───┘    Insert Document (status='RAW')        │
│                                       Push doc_id to asyncio.Queue          │
│                                                                             │
│                                    │                                        │
│                                    ▼                                        │
│                      ┌───────────────────────────┐                          │
│                      │   asyncio.Queue(max=1000) │                          │
│                      └─────────────┬─────────────┘                          │
│                                    │                                        │
│          ┌─────────────────────────┴─────────────────────────┐              │
│          ▼                                                   ▼              │
│  Worker 1 (Persistent Task)                          Worker 2 (Persistent)  │
│    ├── Pop doc_id                                      ├── Pop doc_id       │
│    ├── NER & Entity Normalization                      ├── NER & Normalizer │

└─────────────────────────────────────────────────────────────────────────────┘
```

### 1.3 Technical Specification
1. **Scheduler Refactor (`backend/app/services/scheduler_service.py`):**
   - Retain 5-second tick loop.
   - Bounded concurrency: Fetch up to 10 sources concurrently using `asyncio.Semaphore(10)` and `asyncio.gather(*tasks, return_exceptions=True)`.
   - Dedicated `per_source_timeout = 15.0` seconds strictly for HTTP network fetching and raw storage.
2. **Document Ingestion Decoupling (`backend/app/services/ingestion.py`):**
   - Set `trigger_pipeline=False` by default in scheduled runs.
   - Newly inserted documents are persisted with `processing_status = 'RAW'`.
   - Ingestion run metrics track `documents_discovered`, `documents_inserted`, and `duplicates_skipped` without waiting for downstream intelligence extraction.
   - Enqueue new `doc_id` into `processing_queue: asyncio.Queue[uuid.UUID]`.
3. **Pipeline Worker Pool (`backend/app/services/pipeline_worker.py` - NEW):**
   - 2 to 4 persistent background async tasks managed by the application lifespan.
   - Worker lifecycle: Pop `doc_id` -> open isolated `SessionLocal()` -> invoke `pipeline_service.process_document_end_to_end(db, doc_id)` -> commit -> release session.
   - **Failure Isolation:** If extraction on a document fails, it is marked `processing_status = 'FAILED'`, error recorded in `raw_metadata['pipeline_error']`, and worker continues to next document.
   - **Backpressure & Concurrency Limits:** Queue size capped at 1,000. If full, fetchers yield to prevent memory bloat.
   - **Restart Recovery:** On startup, query `Document` where `processing_status IN ('RAW', 'NORMALIZED', 'EXTRACTION_PENDING')` ordered by `ingested_at ASC`, limit 100, and enqueue for processing.
   - **Graceful Shutdown:** On SIGTERM / application shutdown, signal workers to stop, drain in-flight processing, and close queue cleanly.

## Phase 3 — Primary Source Ingestion Engine

### 3.1 Collector Architecture
Existing collectors in `backend/app/collectors/`:
- `RSSCollector` (handles standard RSS 2.0 and ATOM feeds).
- `APICollector` (generic JSON REST collector).

New specialized collectors required:
1. **`GeoJSONCollector` (`backend/app/collectors/geojson.py` - NEW):**
   - Polls USGS Earthquakes GeoJSON feed (`summary/4.5_day.geojson`).
   - Parses `FeatureCollection` items: magnitude (`properties.mag`), place description (`properties.place`), event timestamp (`properties.time`), exact geographic coordinates (`geometry.coordinates`: `[lon, lat, depth]`).
   - Normalizes directly into `ExtractedEventItem` of type `EventType.DISASTER` and maps to canonical entities (`Country`, `City`).
2. **`OFACCollector` (`backend/app/collectors/ofac.py` - NEW):**
   - Parses official US Treasury `sdn.xml` file.
   - Extracts designated individuals, vessels, aircraft, and corporate entities.
   - Generates high-confidence `sanctions` events and `sanctioned_by` relationship edges.
3. **`CentralBankRSSCollector` (`backend/app/collectors/central_bank.py` - NEW):**
   - Specialized parser for Federal Reserve, ECB, BoE, and RBI feeds.
   - Filters statements for policy committee decisions (FOMC statements, ECB monetary decisions).
   - Extracts basis point rate deltas and statement dates.

### 3.2 Deduplication & Provenance Rules
- Content hashing uses SHA-256 over normalized text: `sha256(f"{source_name}:{external_id}:{published_at}:{clean_content}".encode())`.
- For USGS seismic data, `external_id` is the USGS event ID (e.g. `us7000m123`). Exact coordinate deduplication prevents duplicate earthquake records on minor magnitude updates.
- All documents retain `raw_metadata` storing provider HTTP headers, `ETag`, and exact feed URLs.

### 4.2 Polling Service Implementation (`backend/app/services/market_ingestion_service.py` - NEW)
- Autonomous background loop scheduled every 60 seconds.
- Queries `market_assets` table for active assets.
- Calls provider adapters (`CoinGeckoProvider`, `FinnhubProvider`, `ECBFXProvider`, `FREDYieldProvider`).
- Inserts validated records into `market_observations`:
  - `market_asset_id`: Asset UUID.
  - `timestamp`: UTC exchange / tick timestamp.
  - `open`, `high`, `low`, `close`, `volume`.
  - `source`: Provider name (`CoinGecko`, `Finnhub`, `ECB`, `FRED`).
  - `interval`: `'1m'`, `'5m'`, `'1h'`, `'1d'`.
  - `metadata`: `{"venue": venue, "bid": bid, "ask": ask, "latency_ms": latency}`.
- Quality guard: Ingests only if timestamp is monotonic and price $> 0$.

### 4.3 Non-Null Event-Market Correlation Protocol
- In `backend/app/services/correlation_service.py`:
  - When an event occurs at timestamp $T$, the service queries `market_observations` for:
    - `pre_event_price`: closest observation in $[T - 2\text{h}, T]$.
    - `post_event_price`: closest observation in $[T, T + 2\text{h}]$ (or $24\text{h}$).
  - **Empirical Calculation:**
    $$\text{return\_percent} = \frac{\text{post\_price} - \text{pre\_price}}{\text{pre\_price}} \times 100$$
  - **Weekend / Market Closed Handling:** If exchange was closed and no observations exist within the window, `return_percent` remains explicitly `NULL`, and `metadata['status'] = 'MARKET_CLOSED'`. No synthetic zeroes.

## Phase 6 — Disaster Intelligence Pipeline

### 6.1 Structured Hazards Processing
- **Source:** USGS Earthquake Hazards API (`summary/4.5_day.geojson`).
- **Trigger Rule:** `properties.mag >= 4.5`.
- **Pipeline Stages:**
  1. Parse GeoJSON feature properties (`mag`, `place`, `time`, `url`).
  2. Parse geometry: `latitude = coordinates[1]`, `longitude = coordinates[0]`, `depth_km = coordinates[2]`.
  3. Reverse geocode coordinates deterministically using internal bounding boxes to locate country and nearest major city canonical entities.
  4. Create `Document` with `source = 'USGS'`.
  5. Create `ExtractedEvent`:
     - `event_type = 'disaster'`
     - `event_title = f"M{mag:.1f} Earthquake - {place}"`
     - `event_time = epoch_to_utc(time)`
     - `importance_score = min(1.0, 0.5 + (mag - 4.5) * 0.15)`
     - `confidence = 0.99` (Instrumental ground truth)
     - `entities = [Country, City]`
  6. Cluster into `EventCluster` within 100km radius and 24-hour window (grouping foreshocks/aftershocks).
  7. If `mag >= 6.5`, generate immediate `Alert` of severity `CRITICAL`.

### 7.2 Strict Extraction & Grounding Rules
For each event extracted:
1. **Trigger Phrase Match:** Must match verified trigger lexicon (e.g. `"rate hike"`, `"missile strike"`, `"tariffs imposed"`, `"declared state of emergency"`).
2. **Entity Requirement:** Must bind to at least one canonical sovereign or institutional entity (`Country`, `CentralBank`, `Corporation`, `Agency`).
3. **Temporal Grounding:** Event timestamp must be derived from publication date or explicit parsed text temporal expressions, never default to run execution time.
4. **Exact Span Grounding:** Must record character start and end offsets (`start_char`, `end_char`) of the triggering sentence in document text.
5. **False-Positive Filtering:**
   - Negation filtering: Sentences matching `\b(denied|refuted|no plans to|did not)\b` reject the trigger.
   - Sports / Entertainment stop-words: Rejects documents matching terms like `"championship"`, `"premier league"`, `"box office"`, `"hollywood"`.
   - Opinion / Op-Ed suppression: Documents flagged as editorial or opinion pieces have confidence downgraded by 0.30.

### 8.2 Root Cause Fix for 0 Relationships in Production
The forensic audit proved `entity_relationships = 0` because:
1. `DeterministicRelationshipExtractor` searched sentences only for canonical names (e.g. `"United States"`, `"Russian Federation"`). Most news text uses abbreviations or aliases (`"US"`, `"USA"`, `"Washington"`, `"Russia"`, `"Moscow"`, `"Kremlin"`).
2. The rules lacked alias-aware co-occurrence expansion.

**The Fix in `backend/app/extractors/relationship.py`:**
- Connect `DeterministicRelationshipExtractor` to `_ENTITY_KNOWLEDGE_BASE` alias dictionary.
- Search each sentence for aliases of known entities.
- If two entities co-occur in the same sentence with an active/passive predicate rule:
  - Verify predicate is not negated.
  - Calculate extraction confidence ($\ge 0.80$).
  - Store sentence text in `evidence` and record character offsets in `metadata`.
  - Persist to `entity_relationships` using `ON CONFLICT DO NOTHING` on `uq_entity_relationship_source_target_type`.

## Phase 12 — Production Safety & Zero-Synthetic Data Protocol

### 12.1 Safeguards
1. **Strict Test Database Isolation:**
   - `conftest.py` inspects `DATABASE_URL`. If `DATABASE_URL` matches production `global_intelligence`, the test suite aborts immediately with an exit code 1.
2. **Idempotency Invariants:**
   - Unique constraints on `Document.content_hash`, `ExtractedEvent.id`, `EntityRelationship(source, target, type)`, and `MarketObservation(asset_id, timestamp, interval)`.
3. **Source-Specific Failure Isolation:**
   - Every collector run is wrapped in an isolated `try/except`. If an external endpoint returns 403, 404, or times out, only that source's `consecutive_failures` increments. All other sources continue unaffected.
4. **Zero Synthetic Records:**
   - No mock data generators or deterministic test bars are allowed to execute in production runtime. All rows must carry authentic external provider IDs.
