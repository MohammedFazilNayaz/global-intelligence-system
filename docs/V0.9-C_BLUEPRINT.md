## 1. Executive Summary & Phase Objective

### 1.1 Objective
Phase **V0.9-C** establishes the **visual rendering foundation** of the Interactive Global Intelligence Globe. It bridges the verified backend geographic contract delivered in V0.9-B (`/api/v1/geo/features`) with a responsive, zero-dependency dual-mode canvas interface in the frontend.

The Globe is an analytical instrument for situational awareness. It delivers:
1. **Default 3D View:** Orthographic spherical projection conveying accurate geodesic curvature and planetary context without spatial distortion.
2. **Alternate 2D View:** Equirectangular cylindrical projection displaying all 11 global operational theatres simultaneously at a single glance.
3. **Seamless State Parity:** 2D and 3D views share the exact same dataset, filter parameters, selection state, and coordinate anchors.
4. **Strict Grounding Enforcement:** Zero fabricated coordinates. ### 2.2 Selected Technology: Native HTML5 Canvas 2D with High-Precision Projection Math

**Architectural Rationale:**
1. **Zero Added Dependencies:** Preserves the lean frontend (`package.json` unchanged). No external binary assets, WebGL shaders, or version mismatches with React 19.
2. **Absolute Reliability:** Canvas 2D is supported by 100% of modern browsers, starts cleanly, consumes minimal memory, and renders vector paths and markers directly without WebGL context loss risks.
3. **Full Algorithmic Control:** Orthographic spherical projection and equirectangular projection are mathematically deterministic, closed-form equations. Custom implementation prevents black-box rendering bugs and coordinate drift.
4. **High-DPI Retina Crispness:** Canvas scaling via `window.devicePixelRatio` guarantees sharp sub-pixel vector rendering on high-resolution displays.
5. **Seamless Headless Testing:** The projection engine is separated into pure TypeScript functions, allowing 100% test coverage in standard Vitest/jsdom without headless browser overhead.

### 2.3 Strict Dependency Discipline
The zero-added-dependency mandate is binding:
- **Rule:** Do NOT add Three.js, d3-geo, deck.gl, Leaflet, OpenLayers, or Mapbox to `package.json`.
- **Exception Protocol:** If implementation evidence definitively demonstrates that native Canvas 2D cannot satisfy the defined rendering performance or projection accuracy requirements, the developer **must STOP immediately and request user review** with empirical benchmark data rather than silently installing dependencies.

### 3.1 3D Orthographic Projection (Spherical Perspective)
The orthographic projection simulates looking at the Earth from an infinite distance in space. It is defined by the camera center $(\lambda_0, \phi_0)$ in radians and the globe radius $R$ in pixels:

1. **Angular Central Distance ($c$):**
   $$\cos c = \sin \phi_0 \sin \phi + \cos \phi_0 \cos \phi \cos(\lambda - \lambda_0)$$
2. **Back-Hemisphere Occlusion Invariant:**
   - If $\cos c < 0$: The point is on the far side of the planet. It is **immediately culled** (`visible = false`).
   - If $\cos c \ge 0$: The point is on the visible front hemisphere.
3. **Cartesian Screen Coordinates ($x, y$):**
   $$x = x_{\text{center}} + R \cdot \cos \phi \sin(\lambda - \lambda_0)$$
   $$y = y_{\text{center}} - R \cdot \left(\cos \phi_0 \sin \phi - \sin \phi_0 \cos \phi \cos(\lambda - \lambda_0)\right)$$
4. **Limb Attenuation (Depth):**
   $$z_{\text{depth}} = \cos c$$
   Features near the globe edge ($\cos c \to 0$) have their hit-test radii adjusted to account for perspective foreshortening.

### 3.2 2D Equirectangular Projection (Cylindrical Overview)
The 2D projection maps longitude and latitude linearly onto Cartesian space:
1. **Screen Coordinates ($x, y$):**
   $$x = x_{\text{center}} + \left(\frac{\text{normalize}(\lambda - \lambda_0)}{2\pi}\right) \cdot W_{\text{map}} \cdot \text{zoom}$$
   $$y = y_{\text{center}} - \left(\frac{\phi - \phi_0}{\pi}\right) \cdot H_{\text{map}} \cdot \text{zoom}$$
2. **Date-Line Normalization:**
   $$\text{normalize}(\Delta\lambda) = ((\Delta\lambda + \pi) \pmod{2\pi}) - \pi$$
3. **Viewport Culling:** Points where $x < -50$, $x > W_{\text{canvas}} + 50$, $y < -50$, or $y > H_{\text{canvas}} + 50$ are culled before drawing.

### 3.3 Inverse Projections (Screen $[x, y] \to [\lambda, \phi]$)
- **In 3D:** Given screen point $(x, y)$ relative to globe center $(x_c, y_c)$:
  $$\rho = \sqrt{(x - x_c)^2 + (y - y_c)^2}$$
  If $\rho > R$, the point is outside the sphere (no terrestrial hit).
  If $\rho \le R$:
  $$c = \arcsin\left(\frac{\rho}{R}\right)$$
  $$\phi = \arcsin\left(\cos c \sin \phi_0 + \frac{(y_c - y) \sin c \cos \phi_0}{\rho}\right)$$
  $$\lambda = \lambda_0 + \arctan2\left((x - x_c) \sin c, \rho \cos \phi_0 \cos c - (y_c - y) \sin \phi_0 \sin c\right)$$
- **In 2D:**
  $$\lambda = \lambda_0 + \left(\frac{x - x_c}{W_{\text{map}} \cdot \text{zoom}}\right) \cdot 360^\circ$$
  $$\phi = \phi_0 - \left(\frac{y - y_c}{H_{\text{map}} \cdot \text{zoom}}\right) \cdot 180^\circ$$

### 3.4 Explicit Numerical Tolerances
The implementation must adhere to strict mathematical precision standards:
- **3D Orthographic Forward Projection:** Screen coordinate error $\epsilon_x, \epsilon_y \le 10^{-6}\text{ pixels}$.
- **3D Orthographic Inverse Projection:** Angular error $\epsilon_\lambda, \epsilon_\phi \le 10^{-5}\text{ degrees}$ ($<1.11\text{ meters}$ on Earth surface).
- **2D Equirectangular Forward Projection:** Screen coordinate error $\epsilon_x, \epsilon_y \le 10^{-6}\text{ pixels}$.
- **2D Equirectangular Inverse Projection:** Angular error $\epsilon_\lambda, \epsilon_\phi \le 10^{-5}\text{ degrees}$.
- **Round-Trip Identity:** For any visible point $(\lambda, \phi)$, $\text{unproject}(\text{project}(\lambda, \phi))$ must equal $(\lambda, \phi)$ within $\pm 0.0001^\circ$.

## 4. Date-Line & Singularity Handling

The projection engine must robustly handle topological edge cases without numerical instability:

### 4.1 Date-Line Proximity and Crossing ($\pm 180^\circ$)
- Points near $+179.5^\circ$ and $-179.5^\circ$ longitude are only $1.0^\circ$ apart geographically:
  - **3D Orthographic:** Rotation across the antimeridian is continuous. When camera is centered at $\lambda_0 = 180^\circ$, points at $+179.5^\circ$ and $-179.5^\circ$ appear adjacent on opposite sides of the central meridian ($x \approx x_c \pm R \sin(0.5^\circ)$) without flipping.
  - **2D Equirectangular:** Relative longitude difference must use modular wrapping $\text{normalize}(\Delta \lambda)$. Distance calculations between $+179.5^\circ$ and $-179.5^\circ$ must yield $1.0^\circ$, not $359.0^\circ$.
- **Boundary Verification:** Coordinates at exactly $+180.0^\circ$ and $-180.0^\circ$ map identically to the same terrestrial line.

### 4.2 Singularities & Bounds Validation
- **Poles ($\phi = \pm 90.0^\circ$):** At the North/South poles, $\cos \phi = 0$. Forward projection simplifies to $x = x_c$, $y = y_c \mp R \cos \phi_0$. Inverse projection at $\rho = 0$ when $\phi_0 = 90^\circ$ resolves cleanly to $\phi = 90^\circ$ without division by zero.
- **Globe Limb ($\rho = R, \cos c = 0$):** Points exactly on the limb horizon have $z_{\text{depth}} = 0$ and remain visible.
- **Invalid Coordinates:** Any feature with $|\phi| > 90.0^\circ$, $|\lambda| > 180.0^\circ$, `NaN`, or non-numeric coordinates is rejected during normalization and assigned to `UNRESOLVED` (zero pixels rendered).

The Globe strictly honors the four-state model certified in V0.9-B:

### 5.1 Regional Geographic Integrity Rules
1. **Never fabricate point coordinates:** A country-level event (e.g., nationwide economic reform in Germany) or maritime event (e.g., Red Sea shipping incident) must **never** be assigned a synthesized centroid pin, average coordinate, or jittered dot.
2. **Authoritative Polygon Prerequisite:** A regional contour or boundary highlight may **only** be drawn if an authoritative, provenance-backed geographic polygon exists for that region (e.g., sovereign boundary from canonical gazetteer).
3. **Non-Point Representation Fallback:** If authoritative polygon geometry is unavailable, the regional event must be presented as a **non-point representation** (e.g., docked regional summary chip, off-canvas regional list, or status banner). It must never be converted into a point marker.

### 5.2 Unresolved Quarantine
Events lacking spatial grounding (`location_state == UNRESOLVED`) are strictly quarantined:
- Zero pixels drawn on the 3D globe or 2D map.
- Counted in the header HUD badge (`"32 events spatially unlocated (quarantined)"`).
- Retained in application state for consumption by the future Spatially Unresolved Intelligence Tray.

## 7. The 150 Individual Marker Ceiling & Density Governor

### 7.1 Individual Feature Policy
To preserve analytical clarity and prevent visual clutter on screen:
- The canvas render loop draws **at most 150 individual geographic event features**.
- Each rendered item corresponds 1-to-1 with an authentic event feature from the GeoJSON dataset.
- **Zero Synthetic Aggregation Points:** The system will **never** calculate synthetic "cluster centroids" or average coordinates to represent groups of events. Regional aggregation visualization is explicitly deferred until formal provenance-backed geographic aggregation semantics are established.

### 7.2 Deterministic Selection Policy
When the active query returns more than 150 candidate spatial features:
1. Candidate features with valid point geometry are sorted deterministically:
   - Primary sort: `importance DESC`
   - Secondary sort: `confidence DESC`
   - Tertiary sort: `event_time DESC`
   - Deterministic tie-breaker: `id ASC`
2. The top 150 features from this sorted list are rendered as individual markers.
3. Excluded features ($> 150$) remain in application memory and in the API pagination state.
4. The HUD displays an informative density indicator: `"Displaying 150 highest-priority events (of 214 matching)"`.

## 8. Read-Only Invariance & Security

The Interactive Globe is an air-gapped, strictly **read-only visual consumer**:
1. **Zero State Mutation:** All user interactions (rotating, panning, zooming, toggling 2D/3D, clicking markers, changing filters) mutate **only local client state**.
2. **Read-Only API Calls:** The client makes only HTTP `GET` requests against `/api/v1/geo/features` and `/api/v1/geo/events/{id}`.
3. **Zero Side Effects:** Globe operations cannot:
   - Trigger RSS, API, or GeoJSON ingestion.
   - Trigger pipeline worker runs or scheduler executions.
   - Mutate extracted events, clusters, entities, or relationships.
   - Record market observations or economic indicators.
   - Modify configuration or database records.

## 9. Error, Loading, Empty & Edge-Case Failure States

The rendering architecture defines explicit behavior for all failure and edge conditions:

| State | Trigger Condition | Visual Presentation & Behavior |
|---|---|---|
| **Loading** | Initial load or filter change in progress | Non-blocking dark overlay (`rgba(7, 11, 20, 0.70)`) with institutional spinner and notice: `"Projecting Geographic Intelligence..."`. Existing basemap remains visible. |
| **Empty Dataset** | Filters yield 0 matching features | Basemap, graticule, and continents render cleanly. HUD banner: `"No intelligence events match the active filters. Adjust importance or event type filters to view data."`. |
| **Malformed GeoJSON** | Response fails schema validation | Offending features quarantined with console warning; valid features render cleanly. Non-fatal HUD alert: `"1 item contained invalid spatial data and was quarantined."`. |
| **API Timeout** | Backend request exceeds 8000ms | Retains last valid rendered map. Displays warning banner: `"Network request timed out. Retrying in 15s..."` with manual `[Retry]` button. |
| **API Error (500/502)**| Server returns error code | Non-fatal warning docked at top: `"Unable to update features (Error 500). Displaying cached intelligence."`. Zero crash. |
| **Browser Window Resize** | Window resized or split-screen toggled | `ResizeObserver` monitors canvas container. Recalculates canvas pixel dimensions and updates projection center without camera jump or coordinate drift. |
| **Device Pixel Ratio Change** | Window moved between standard and Retina displays | Detects `window.devicePixelRatio` change via media query listener. Rescales canvas backing store (`canvas.width = cssWidth * dpr`) to maintain razor-sharp rendering. |
