## 1. Executive Summary & Product Objective

### 1.1 Purpose of the Interactive Globe
The **Interactive Global Intelligence Globe** represents the primary geospatial situational awareness surface of the Global Intelligence Platform. It transitions the system from traditional tabular, card-based, and list-oriented navigation into a continuous, interactive global operating picture.

### 1.2 What the Globe Is NOT
Under strict architectural doctrine, the Globe is explicitly defined by what it **refuses** to be:
- **NOT a Decorative 3D Earth:** It is not a cosmetic marketing widget or an uninformative spinning graphic. Every pixel, node, arc, and boundary represents verified, structured intelligence.
- **NOT a Generic News Map:** It does not scatter hundreds of unverified, unclustered news headlines across geographic space.
- **NOT a Separate Data Pipeline:** It does not introduce independent ingest loops, scrapers, or parallel storage engines.
- **NOT a New Database:** It does not introduce Neo4j, MongoDB, or independent geospatial datastores. It operates as a high-performance visual consumer of the existing PostgreSQL / SQLAlchemy relational schema.
- **NOT a Replacement for Analytical Desks:** It complements rather than replaces the Overview, Live Feed, Economic Desk, Market Intelligence, and System Coverage views.

### 1.3 Core Capability Pillars
The Globe is an interactive spatial projection engine binding eight core dimensions of the platform:
1. **EVENTS:** Incident taxonomy across 23 standardized geopolitical and economic categories.
2. **ENTITIES:** Sovereign states, central banks, corporations, cities, and leaders anchored to canonical records.
3. **RELATIONSHIPS:** Grounded, sentence-quoted entity relationships rendered as contextual spatial arcs.
4. **LOCATIONS:** Multi-fidelity geographic resolution (`RESOLVED`, `APPROXIMATE`, `REGIONAL`, `UNRESOLVED`) with an absolute prohibition against coordinate fabrication.
5. **IMPACT:** Retrospective, non-causal economic and market context within empirical observation windows.
6. **MARKET CONTEXT:** Real-time and contemporaneous telemetry across the exact 16 canonical assets.
7. **SOURCE EVIDENCE:** Full character-span quote provenance, primary source attribution, and ingestion run traceability.
8. **TIME:** Continuous temporal exploration from live real-time feeds to multi-day historical scrubbing.

## 3. Globe Data Model & Canonical Map Objects

The Globe visualizer operates over ten canonical map primitives. Every primitive defines a strict contract:

```
                  ┌───────────────────────────────┐
                  │      CANONICAL MAP OBJECTS    │
                  └──────────────┬────────────────┘
                                 │
         ┌───────────────────────┼───────────────────────┐
         ▼                       ▼                       ▼
  ┌──────────────┐        ┌──────────────┐        ┌──────────────┐
  │  EVENT_PIN   │        │ EVENT_CLUSTER│        │RELATION_ARC  │
  └──────────────┘        └──────────────┘        └──────────────┘
         │                       │                       │
         ▼                       ▼                       ▼
  ┌──────────────┐        ┌──────────────┐        ┌──────────────┐
  │DISASTER_EPIC │        │ ENTITY_ANCHOR│        │COVERAGE_POLY │
  └──────────────┘        └──────────────┘        └──────────────┘
```

### 3.1 Object Definitions

#### 1. `EVENT_PIN`
- **Description:** A discrete incident anchored to a point or municipal center.
- **Required Fields:** `id` (UUID), `title` (string), `event_type` (string), `resolution_state` (`RESOLVED` | `APPROXIMATE`), `coordinates` (`[lon, lat]`), `event_time` (ISO-8601 UTC), `importance` (0.0–1.0), `confidence` (0.0–1.0), `freshness` (enum), `primary_source` (bool).
- **Optional Fields:** `cluster_id` (UUID), `magnitude` (float for disasters), `summary` (string).
- **Visual Encoding:** Geometric glyph keyed to event type, sized by importance, colored by category, animated pulse if `CURRENT`.

#### 2. `EVENT_CLUSTER_NODE`
- **Description:** A spatial or semantic aggregation of multiple events referring to the same real-world incident.
- **Required Fields:** `cluster_id` (UUID), `canonical_title` (string), `event_count` (int), `unique_source_count` (int), `coordinates` (`[lon, lat]`), `event_type` (dominant), `max_importance` (float), `earliest_time` (UTC), `latest_time` (UTC).
- **Visual Encoding:** Concentric ring marker with numeric event badge; radius scales logarithmically with event volume.

#### 3. `ENTITY_ANCHOR`
- **Description:** A permanent geographic feature (capital city, sovereign border, central bank headquarters).
- **Required Fields:** `entity_id` (UUID), `canonical_name` (string), `entity_type` (`COUNTRY` | `CITY` | `LOCATION` | `CENTRAL_BANK`), `country_code` (ISO-2), `coordinates` (`[lon, lat]`).
- **Visual Encoding:** Subdued anchor dot with typographic label at medium-to-high zoom levels.

#### 4. `RELATIONSHIP_ARC`
- **Description:** A directional or bidirectional dynamic vector between two spatial entities.
- **Required Fields:** `id` (UUID), `source_coords` (`[lon, lat]`), `target_coords` (`[lon, lat]`), `relationship_type` (enum), `confidence` (float), `evidence` (string quote).
- **Visual Encoding:** 3D great-circle parabolic bezier arc with animated directional pulse; color-coded by predicate (e.g. green for alliance, amber for trade, red for sanctions).

#### 5. `DISASTER_EPICENTER`
- **Description:** Authoritative natural hazard point (seismic event, volcanic eruption).
- **Required Fields:** `event_id` (UUID), `coordinates` (`[lon, lat]`), `depth_km` (float), `magnitude` (float), `event_time` (UTC), `source` (`USGS`).
- **Visual Encoding:** Concentric shockwave rings expanding radially; radius proportional to Richter magnitude; color mapped to depth/magnitude.

#### 6. `COVERAGE_POLYGON`
- **Description:** Multi-polygon boundary representing an operational theatre or country jurisdiction.
- **Required Fields:** `region_name` (string), `iso_codes` (string[]), `quality_rating` (`GOOD` | `PARTIAL` | `POOR` | `NONE`), `active_sources` (int), `iqi_score` (float).
- **Visual Encoding:** Semi-transparent choropleth tint with diagonal hatched pattern over blind spots (`PARTIAL` / `POOR`).

#### 7. `MARKET_TICKER_BADGE`
- **Description:** Contemporaneous pricing context for assets tied to regional events.
- **Required Fields:** `symbol` (1 of 16 canonical), `current_price` (float), `return_percent` (float), `provider` (string), `timestamp` (UTC).
- **Visual Encoding:** Compact floating HUD card docked to the regional viewport.

## 4. Geographic Representation & Coordinate Integrity

### 4.1 Strict Grounding Doctrine (Zero Coordinate Fabrication)
> [!IMPORTANT]
> Under no circumstances will coordinates be generated, interpolated from synthetic centroids, or randomly jittered. Fabricating geospatial data in an institutional intelligence platform destroys analytical integrity.

### 4.2 Location Resolution States
Every intelligence item is deterministically assigned one of four spatial states:

```
┌─────────────────┬───────────────────────────────┬───────────────────────────────┐
│ State           │ Qualifying Criteria           │ Visual Rendering on Globe     │
├─────────────────┼───────────────────────────────┼───────────────────────────────┤
│ **RESOLVED**    │ Exact point coordinates from  │ Sharp illuminated pin at      │
│                 │ primary sensor (USGS GeoJSON) │ exact coordinate with micro-  │
│                 │ or verified city coordinates. │ pulse radar ring.             │
├─────────────────┼───────────────────────────────┼───────────────────────────────┤
│ **APPROXIMATE** │ Municipal boundary, airport,  │ Softened circular halo (15km  │
│                 │ naval base, or district.      │ visual radius) with dotted    │
│                 │                               │ uncertainty perimeter.        │
├─────────────────┼───────────────────────────────┼───────────────────────────────┤
│ **REGIONAL**    │ Country-level, sea corridor   │ Full country boundary contour │
│                 │ (e.g. "Red Sea"), or province │ illuminated; centroid badge   │
│                 │ without point coordinates.    │ indicates territorial scope.  │
├─────────────────┼───────────────────────────────┼───────────────────────────────┤
│ **UNRESOLVED**  │ Extracted event lacking       │ Strictly NEVER drawn on map.  │
│                 │ geocodable entity or sensor   │ Docked in dedicated off-map   │
│                 │ coordinates (32 curr events). │ "Unresolved Intelligence Tray"│
└─────────────────┴───────────────────────────────┴───────────────────────────────┘
```

### 4.3 Complex Spatial Topologies
- **Maritime Incidents (e.g. Red Sea, Bab el-Mandeb):** Bound to canonical maritime geopolitical polygons with centroid reference points.
- **Border Incidents (e.g. Ukraine-Russia border):** Represented as a frontier line segment highlighted between the two territorial jurisdictions.
- **Transnational Bilateral Events (e.g. US-Germany Clean Energy Pact):** Rendered as twin country highlights connected by an active diplomatic relationship arc.

### 9.1 Relational Arc Mechanics

- **Predicate Styling:**
  - `ALLIED_WITH`: Luminous Emerald solid arc (`#10B981`)
  - `SANCTIONS`: Amber-Red dashed arc (`#EF4444`)
  - `TRADES_WITH` / `EXPORTS`: Indigo flowing arc (`#6366F1`)
  - `LEADS` / `HEADQUARTERED_IN`: Local radial beam
- **Clutter Elimination:** Arcs are **hidden by default** on global views. Arcs only render when:
  1. An entity or event is actively selected (displaying its direct 1-hop connections).
  2. The analyst toggles the dedicated "Relational Overlay" with a confidence threshold $\ge 0.85$.
  3. No more than 20 concurrent arcs are drawn simultaneously.

## 11. Real-Time Disaster Intelligence Layer

### 11.1 Dedicated Multi-Hazard Layer
- **USGS Seismic Ingestion:** Plots exact earthquake hypocenters from GeoJSON feeds.
- **Visual Wave Expansion:** Every earthquake emits three concentric shockwave pulses. The outer ring radius scales with magnitude:
  $$\text{Radius (pixels)} = 12 \times 1.4^{(M - 4.0)}$$
- **Severity Classification:**
  - $M < 4.5$: Minor (Green ring)
  - $4.5 \le M < 6.0$: Moderate (Yellow/Amber ring)
  - $6.0 \le M < 7.0$: Significant (Orange ring)
  - $M \ge 7.0$: Major / Catastrophic (Pulsing Red double ring)

## 12. Source Provenance & Evidence Verification

The Globe answers the foundational analytical question: **"Why is this event on the map?"**
Every event detail view exposes an immutable audit trail:
1. **Source Attribution:** Exact syndication feed (e.g. *US Federal Reserve Press*, *Deutsche Welle*, *USGS*).
2. **Primary vs Secondary Tag:** Explicit badge verifying official sovereign/sensor provenance vs news wire.
3. **Verbatim Evidence:** Extracted sentence quote with exact character coordinates (`start_char` to `end_char`).
4. **Ingestion Metadata:** Ingestion Run UUID, HTTP status code, and millisecond fetch latency.

## 13. Operational Freshness Engine Integration

The Globe implements the platform's deterministic freshness model:
- `CURRENT` ($\le 24\text{ hours}$): Fully saturated visual tone, pulsating beacon.
- `RECENT` ($24\text{ hours} - 7\text{ days}$): Normal saturation, static marker.
- `STALE` ($7\text{ days} - 30\text{ days}$): 40% desaturation, thinner stroke.
- `HISTORICAL` ($> 30\text{ days}$): Slate monochrome wireframe.
- `UNKNOWN`: Muted gray glyph.

## 15. Performance & Scalability Architecture

### 15.1 Scaling Tiers
| Volume Tier | Technical Strategy |
|---|---|
| **100 Events** | Direct client-side WebGL / SVG rendering; no spatial tree required. |
| **1,000 Events** | Dynamic client-side spatial indexing via QuadTree; viewport culling active. |

### 15.2 Viewport Culling & Hardware Acceleration
- All point primitives are drawn onto a hardware-accelerated WebGL or 2D Canvas context.
- Objects outside the camera view frustum or on the occluded back-hemisphere of the 3D globe are culled before the render pass.
- Maximum active screen elements capped at 150 items to maintain constant 60 FPS performance on standard integrated graphics.

## 16. Real-Time Update Architecture

### 16.1 Protocol Decision: Lightweight Incremental Polling
- **Evaluated Protocols:** WebSockets vs Server-Sent Events (SSE) vs HTTP Delta Polling.
- **Architectural Decision: INCREMENTAL DELTA POLLING (15s Cadence)**.
  - **Rationale:** The backend ingestion scheduler operates on 300s–900s polling cadences. WebSockets introduce stateful connection overhead, connection drops, and proxy firewall complexities with zero benefit for 15s refresh cycles.
  - **Implementation:** Client queries `GET /api/v1/intelligence/live?since={last_observed_timestamp}` every 15 seconds.
  - **Strict Constraint:** The Globe is a 100% read-only visual consumer. It never triggers backend source fetching or writes to the database.

## 18. API Contracts & Service Layer

To ensure optimal performance and avoid transferring bulky article text payloads to the map renderer, a dedicated lightweight geospatial endpoint contract is specified:

### 18.1 Proposed Endpoint: `GET /api/v1/geo/features`

- **Query Parameters:**

  - `from_time`, `to_time` (ISO-8601 UTC timestamps)
  - `event_type` (optional string filter)
  - `min_importance` (float 0.0–1.0, default 0.5)
  - `min_confidence` (float 0.0–1.0, default 0.7)
  - `zoom_level` (int 0–12, controls clustering granularity)
  - `limit` (int, default 200, max 500)

- **Parameters:** `page`, `page_size`, `min_importance`.

## 23. What Must NOT Be Added (Deferred & Prohibited Capabilities)

The following concepts are strictly barred from the V0.9 scope:
1. **Generative AI / LLM Narrative Synthesizers:** Zero automated natural-language summary generation. All textual dossier content must consist of structured fields and verbatim source evidence quotes.
2. **Autonomous AI Agents:** Zero autonomous agent loops executing within the client or backend during visualization.
3. **Predictive Forecasting & Trend Extrapolation:** Zero speculative price forecasting, predictive conflict projections, or speculative probability calculations.
4. **Causal Modeling:** Zero causal assertions attributing market movements directly to geopolitical events.
5. **Automated Trading & Trade Signal Generation:** Zero trade recommendations or portfolio allocation signals.
6. **Synthetic or Fabricated Coordinates:** Zero simulated coordinates for unlocated events.
7. **Independent Graph / Geospatial Databases:** Prohibited from adding Neo4j, MongoDB, or standalone GIS servers. Everything runs cleanly on PostgreSQL and FastAPI.
8. **Third-Party Tile Server Dependencies:** No dependence on proprietary, fee-based external tile providers (e.g. Mapbox API keys, Google Maps API) that introduce external latency, privacy leaks, or commercial vendor lock-in.
